# RAG 验收题库（15 题 = 10 有答案题 + 5 无依据题）与判定标准

- **知识库**：默认 collection `rag_knowledge_base`，130 块，全部来自单份文档 `benchmark_test.md`
  （10 条关于北斗卫星导航系统的事实，重复成 130 块）。所有题目均贴着该文档真实内容出题。
- **链路**：直接 import `skills.rag_qa.rag_engine` 调 `chat(question, history=None, user="default")`，
  走完整 RAG 流程：检索 → 重排（阈值 0.3）→ LLM（DeepSeek）→ 反思校验。一次提问算一次，不改问法重试。
- **通过判定**：
  - **有答案题（R01–R10）**：`answer` 中出现预期关键词的**全部要点**（不区分大小写），
    且 `reflection.passed == True`，才算通过。
  - **无依据题（R11–R15）**：文档里没有该信息，系统应**拒答**而非编造。
    判定通过 = `reflection.no_answer == True` **或** `answer` 中出现“无法回答”字样。
    （拒答路径有两条：①重排最高分低于阈值 0.3，引擎直接返回拒答；②LLM 依据 system prompt 自行拒答。）
- **要点分隔符**（沿用 text2sql/eval 约定）：
  - `；` 分隔的要点 = **必须全部命中**；
  - 一个要点内用 `或` 分隔 = 等价写法**任一命中**即可。
- **通过线**：整体 ≥ 12/15（80%）算正常；有答案卷（10 题）和无依据卷（5 题）分别单独统计通过率。
- **题目分层**：R01–R10 为“有答案”卷（覆盖北斗三号开通时间、定位/测速/授时精度、系统组成、
  地基增强精度、北斗三号新增功能、建设原则、短报文通信、兼容互操作等文档中明确存在的事实）；
  R11–R15 为“无依据”卷（总投资金额、卫星设计寿命、首席总设计师、短报文字数上限、运营公司，
  均为文档中**不存在**的信息，用于检验拒答能力/防幻觉）。
